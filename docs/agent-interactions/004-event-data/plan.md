# Events schema and GraphQL

## Domain model

Create dual-purpose TypeORM/GraphQL object types in [`apps/api/src/events/entities`](apps/api/src/events/entities), using explicit table/column names and no nullable domain fields.

- `Event` in [`event.entity.ts`](apps/api/src/events/entities/event.entity.ts), mapped to `events`:
  - `id`: TypeScript `string`; SQLite `varchar` UUID primary key generated by TypeORM; GraphQL `ID!`.
  - `name`: `string`; SQLite `text`, non-null; GraphQL `String!`.
  - `date`: `string`; SQLite `date`, non-null; GraphQL `String!` so the frontend's date-only `YYYY-MM-DD` value has no timezone conversion.
  - `location`: `string`; SQLite `text`, non-null; GraphQL `String!`.
  - `createdAt`: `Date`; SQLite `datetime`, non-null, default `CURRENT_TIMESTAMP`; GraphQL `DateTime!`.
  - `updatedAt`: `Date`; SQLite `datetime`, non-null, maintained by TypeORM; GraphQL `DateTime!`.
  - `feedback`: `Feedback[]`; non-null one-to-many ORM relation, initialized empty and kept out of GraphQL to avoid an unpaginated nested collection.
- `Feedback` in [`feedback.entity.ts`](apps/api/src/events/entities/feedback.entity.ts), mapped to `feedback`:
  - `id`: `string`; SQLite `varchar` UUID primary key generated by TypeORM; GraphQL `ID!`.
  - `eventId`: `string`; SQLite `varchar`, non-null foreign key to `events.id`; GraphQL `ID!`.
  - `event`: `Event`; non-null many-to-one relation; GraphQL `Event!`; deletion of an event is restricted and FK updates cascade.
  - `eventName`: derived `string`; not persisted, non-null GraphQL `String!` backed by the loaded event relation to preserve the existing web read shape without denormalizing the database.
  - `submitterName`: `string`; SQLite `text`, non-null; GraphQL `String!`. This remains a submission field until authentication/User modeling is defined.
  - `rating`: `number`; SQLite `integer`, non-null with a database check from 1 through 5; GraphQL `Int!` to match the web's numeric `StarRating` union.
  - `description`: `string`; SQLite `text`, non-null with a check rejecting blank trimmed descriptions; GraphQL `String!`.
  - `createdAt`: `Date`; SQLite `datetime`, non-null, server-generated with default `CURRENT_TIMESTAMP`; GraphQL `DateTime!`.
- Add explicit indexes supporting newest-first offset pagination and filters: `created_at`, `(event_id, created_at)`, `(event_id, rating, created_at)`, and `(rating, created_at)`.

## Migration and TypeORM registration

- Add one reversible initial migration under [`apps/api/src/database/migrations`](apps/api/src/database/migrations) that creates `events` before `feedback`, including primary/foreign keys, rating/description checks, timestamps, and indexes; its `down` method drops indexes/tables in dependency-safe reverse order.
- Update [`apps/api/src/database/data-source.ts`](apps/api/src/database/data-source.ts) to register `Event` and `Feedback` explicitly and resolve both TypeScript and compiled JavaScript migrations, keeping `synchronize: false` so the migration is the sole schema authority.
- Generate/review the migration through the existing TypeORM CLI and verify `migration:run` and `migration:revert` against an isolated SQLite database. Do not seed placeholder data or commit a database file in this task.

## Events module and GraphQL operations

- Add [`apps/api/src/events/events.module.ts`](apps/api/src/events/events.module.ts) with `TypeOrmModule.forFeature([Event, Feedback])`, the service/resolver, and a singleton PubSub provider.
- Add inputs under [`apps/api/src/events/dto`](apps/api/src/events/dto):
  - `SubmitFeedbackInput`: required non-null `eventId: ID!`, `submitterName: String!`, `rating: Int!`, and `description: String!`; validate UUID, non-blank strings, and rating range 1–5.
  - `FeedbackFilterInput`: nullable `eventId: ID`, nullable unique `ratings: [Int!]`, and non-null defaults `offset: Int! = 0`, `limit: Int! = 20`; validate offset >= 0, limit 1–100, and each rating 1–5.
  - `FeedbackSubscriptionFilterInput`: nullable `eventId: ID` and nullable unique `ratings: [Int!]` for server-side subscription filtering.
- Add a non-entity `FeedbackPage` GraphQL model with non-null `items: [Feedback!]!`, `totalCount: Int!`, `offset: Int!`, `limit: Int!`, and `hasMore: Boolean!`.
- Implement [`apps/api/src/events/events.service.ts`](apps/api/src/events/events.service.ts): list events by date/name; fetch feedback with optional event/rating filters, deterministic `createdAt DESC, id DESC` ordering, relation loading, `findAndCount`, and offset pagination; submit feedback only for an existing event, trim description/name, rely on the database's `CURRENT_TIMESTAMP` default, and return a relation-complete object.
- Implement [`apps/api/src/events/events.resolver.ts`](apps/api/src/events/events.resolver.ts) with:
  - `events: [Event!]!` query.
  - `feedback(filter: FeedbackFilterInput): FeedbackPage!` query.
  - `submitFeedback(input: SubmitFeedbackInput!): Feedback!` mutation.
  - `feedbackAdded(filter: FeedbackSubscriptionFilterInput): Feedback!` subscription, published only after persistence and filtered by optional event/ratings.
- Add `class-validator`, `class-transformer`, and `graphql-subscriptions` through the workspace package manager in [`apps/api/package.json`](apps/api/package.json); enable global input transformation/validation in [`apps/api/src/main.ts`](apps/api/src/main.ts).
